# Main-to-Main Upgrade Stable Decisions

shared_contract: vllm-cl-contract/v1

Main-to-Main Upgrade owns exact upstream target identity, ordered Verified vLLM Alignment candidate recovery, exhaustive global compatibility impact, read-only manifest impact, mandatory regression assignments, child aggregation, and no-finalize reporting. It delegates all model-specific adaptation one-way to Model Adaptation.

Historical mandatory evidence outranks an explicit Git pin, which outranks a correlated candidate. Checkout state, installation metadata, README text, and time correlation never establish a Verified vLLM Alignment without complete mandatory evidence.

Every changed upstream surface must be an affected dependency, a new dependency candidate, or confirmed irrelevant. Unknown impact must be zero. Manifest output is a future-change report and never an applied mutation in this candidate.

Exact-HEAD static inspection can establish that a source surface is absent. It becomes a demonstrated necessary fix for a target workload only after an exact-artifact runtime experiment reaches the target failure boundary and confirms necessity. During delta classification, record that experiment as the validation assignment and map it through the existing v1 dependency IDs; consume its result during child aggregation. Because v1 has no independent necessity-verdict field, identity closure without eligible bounded diagnosis remains `not_verified`. A historical patch not appearing verbatim in main, a failed mixed-version stack, or a repository receiving no patch cannot establish workload necessity. Existing replacement behavior is confirmed present or superseded; source present but consumer/descriptor/DLC Custom Kernel/toolchain/native identities mismatched is artifact or ABI pairing.

For each global surface, preserve repository owner, consumer owners, change kind, paired dependency identities, and validation owner inside the existing v1 evidence/reason fields; this decision does not extend the shared schema or action vocabulary. Investigation can cover more repositories than the final change. Split future PR units by repository responsibility and one principal purpose, not by the number of delivery patch files.

Exact Ticket 06 v12 DeepSeek TP=2 and Llama TP=1 assignments completed operational regression with `authoritativeness: operational_only`, `acceptance_eligible: false`, alignment unchanged, manifest report-only, and finalization `none`. That evidence does not establish Real DLC Hardware acceptance, Verified vLLM Alignment, request-correlated Chunked Prefill, DLC Runtime dispatch, DLCCL/LYP execution, a specific Attention implementation, Triton non-execution, compile/Dynamo non-execution, or rank-to-device allocation. New targets require their own sealed evidence. Dummy, fake-server, DLCsim, static, failed, blocked, and not-verified evidence cannot enable finalization.

The three sealed v1 documents remain the only runtime evidence contracts. This candidate reports alignment unchanged, manifest report-only, and finalize action none.

## Tested And Publication Identities

The Tested Revision is the exact checkout and artifact graph that produced validation evidence. Record its observed clean or dirty state; dirt does not erase evidence identity, but a mismatch between the record and observation blocks assessment. A Publication Candidate is a clean delivery representation constructed from the current target main with only the approved scoped delta. Preserve the Tested Revision as primary evidence; do not rewrite it in place merely to obtain a one-commit PR. Record candidate base and commit SHAs, artifact-graph digest, complete scoped diff/tree identity, excluded paths, and gates rerun against that candidate.

Patch Equivalence is scoped evidence, not acceptance transfer. Stable patch-id can be supporting context across squash or rebase, but is not a schema method and never replaces recomputed scoped Git diff/tree equivalence. Base movement requires candidate reconstruction and every affected source/contract gate. An `artifact_graph_digest` is an externally supplied identity label, not proof that two builds are equivalent. Every candidate therefore requires fresh candidate-bound source, build, and runtime gates plus digest-bound rebuilt artifact references, whether the Tested and Candidate digest strings differ or match.

When publication is proposed, it has independent concurrency and freshness boundaries. Capture a fresh current target-main SHA and PR-branch tip observation plus exact lease expectations; future observations and observations older than handoff generation are invalid. A mismatch requires candidate reconstruction and affected revalidation. Authorization references may be observed for closed schema, digest, candidate/scope binding, and timestamp structure, but without the deferred Stage C trust root their asserted authority and `authorized` value are not trusted. The assessment always returns `human_authorization_required` and cannot establish publication eligibility. A read-only impact analysis with no proposed publication reports no candidate rather than inventing one.

The producer is an external publication-preparation workflow. It may construct the clean candidate and seal `vllm-cl-publication-candidate-handoff/v1`, but it produces the handoff only. Gate, rebuilt artifact, and authorization declarations are references, not inline truth. The package-owned assessor first fail-fast validates the handoff and the digest-bound `vllm-cl-publication-artifact-map/v1`, including candidate identity and the exact reference set, before touching Git. It then resolves each artifact's declared schema, digest, and identity, structurally observes authorization references, and observes Tested Revision, candidate, and remote roots. Git inputs are full SHAs, validated `refs/` names, and validated repository-relative non-option paths; commands disable optional locks/external diff and use option/pathspec terminators. It writes no repository, performs no network operation, always emits finalize `none`, fixes `publication_eligible` false, and can report at most `assessment_complete/not_verified_for_publication`.
