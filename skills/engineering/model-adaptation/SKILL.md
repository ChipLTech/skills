# Model Adaptation

shared_contract: vllm-cl-contract/v1

Use this stable workflow for one approved model and deployment profile. It may consume a one-way Main-to-Main parent assignment, but it does not recover, update, finalize, or claim Verified vLLM Alignment. After Inputs, classify the request as `execution` or `report_only` with `scripts/route-model-adaptation-request.py`.

`execution` follows steps 1-7 below. `report_only` consumes only existing evidence and uses the linked report prompt in `knowledge.md`; it must not build, install, execute devices, benchmark, or mutate a workspace. Its terminal states are `report_complete`, `blocked_missing_evidence`, `blocked_conflicting_evidence`, and `blocked_missing_reader_contract`. It reports route feasibility, adaptation completion, and stable delivery separately and never auto-resolves conflicting evidence.

1. Run preflight over approved model weights, revisions, tokenizer and applicable processor, deployment, repository, contract, hardware requirement, and external artifact identities. Complete when: every required identity is unique and available, or one stable blocker and resume point has been emitted before execution.
2. Build the v1 closed-world capability matrix for text generation, Attention, MLA, MoE, quantization, multimodal, distributed, MTP, tokenizer, processor, and model-specific paths. In each applicable capability's existing evidence record, inspect routing metadata, scoring mode, zero-point/qzeros mode, group size, dtype, layout, and distributed ownership predicates rather than relying on the model name or top-level method. Complete when: every v1 capability is required, resolved conditional, or evidence-backed not applicable, with no unknown or unresolved path; any unsupported active path sets `required_execution_path_supported` false before launch.
3. Inventory compatibility dependencies reachable by the target model. Use the existing dependency identities and evidence to distinguish upstream vLLM, vLLM-CL, PyTorch DLC Backend, DLC_Custom_Kernel Repository, and DLC Runtime/native-stack owners, including pairing-only findings where no repository lacks source. For each active custom-op path, compare the public schema, ordered KernelDesc descriptor ABI, exact DLC Custom Kernel entry ABI/binary, and any bounded adapter. For distributed paths, apply the closed-world [Distributed Collective Qualification](references/distributed-collective-qualification.md): keep frozen v1 artifacts exact, and use exact v2 when topology/payload selection evidence is required. Inventory native DLC_CL, PyTorch ProcessGroup, vLLM communicator, model route, active MoE dispatch/combine, and custom-kernel ABI/binary identity separately. A v2 topology/payload-aware route must bind selector source/binary identity, topology and payload, dtype/layout constraints, root/rank mapping, actual rank permutation, stable strategy/metadata ABI, complete cache key, and validate-then-commit fallback state; world size is not topology evidence. Collect all live identity classes and re-collect them before attestation. Provider seals must pass the closed-world provider contract, match their exact identity class, bind an externally trusted provider identity, and expose an atomic immutable generation before they can be authoritative. Complete when: every required or active conditional capability maps to a traceable dependency identity, each changed dependency is listed exactly once, every fallback success is backed by the selected candidate's complete prerequisites, unsupported or unqualified active routes are closed before launch, and no unrelated work is included.
4. Select the smallest compatibility action and derive TP from the approved weights, model configuration, dtype, quantization, device capacity, and deployment profile. A slow path alone is not a compatibility finding: delegate causal hotspot localization to `diagnosing-bugs`, then consume only a bounded diagnosis that identifies the exact workload, smallest confirmed boundary, execution identity/call count, one-variable result, correctness impact, and remaining uninstrumented scope. Complete when: the action is traceable to the inventory and bounded diagnosis, and the TP decision contains all six evidence classes without inheriting a fixed regression profile.
5. Prepare the real-weight branch and delegate API and lifecycle behavior exclusively to the shared runner contract. When Real DLC Hardware executes, require the runner to delegate the SMI Observation Envelope to `dlc-hardware-observability` without treating it as model acceptance. For async launch failure, Graph, speculative decode, MTP, MLA, MoE, or quantization failures, preserve the last successful lifecycle stage, final worker environments, scheduler/Graph dispatch state, and the first fatal before changing one variable. A diagnostic epoch that stops earlier than the target failure is a new boundary, not evidence for the target cause. Complete when: the sealed run spec and result identities agree, every runner-owned gate and observation point has a terminal state, each diagnostic result states whether it reached the target boundary, and unexecuted Real DLC Hardware, Chunked Prefill, or DLC Runtime evidence remains not verified.
6. Enter the optional Dummy branch only after a sealed real-weight failure and explicit user approval. Complete when: any Dummy result is diagnostic only, acceptance-ineligible, and cannot produce a passed real-weight or Real DLC Hardware handoff.
7. Seal the result and optional parent-child handoff without changing global alignment. Complete when: run, target, candidate, model, deployment, result, parent, and changed-dependency identities close exactly, child status is propagated, and no Verified vLLM Alignment claim is made.

## Stop Semantics

- Missing or ambiguous approved assets stop as `blocked_missing_asset` and resume from model assets.
- Insufficient deployment devices stop as `blocked_missing_hardware` and resume from hardware allocation.
- Repository branch mismatch stops as `blocked_branch_mismatch` before modification.
- Missing or unsupported shared contracts stop as `blocked_missing_contract`.
- Missing request-level or DLC Runtime observations stop as `blocked_missing_observability`.
- A required capability limited to a forbidden execution path stops as `blocked_unsupported_execution_path`.
- An active distributed route without an implementation or exact qualification stops before launch as `blocked_collective_unimplemented` or `blocked_collective_not_qualified`.
- Missing distributed identity, Real DLC Hardware, or launch authorization stops as `blocked_missing_identity`, `blocked_missing_hardware`, or `blocked_missing_authorization` with its exact resume point.
- A package observation without an atomic package-database generation remains `blocked_missing_atomic_package_generation`; it never self-upgrades from repeated filesystem reads.
- A provider code digest or canonical JSON digest is not producer authentication; until an externally verifiable provider-controlled authentication mechanism exists, authoritative seal consumption stops as `blocked_missing_authenticated_provider_seal`.
- Formal acceptance or shared-device mutation requested through the bounded collective producer stops as `blocked_dangerous_operation`.
- A sealed runner assertion failure stops as `failed_assertion`; it is never rewritten as a preflight blocker or downgraded through Dummy.
- Any destination or action that would modify the ticket's read-only vllm-cl repository stops as `blocked_read_only_boundary`.

Fake-server, Dummy, DLCsim, and static evidence are never real-weight or Real DLC Hardware acceptance. Publication only makes this workflow discoverable; it does not broaden Ticket 06 operational evidence.

Claim Boundary: Model Adaptation may produce bounded distributed qualification evidence, but its producer never makes formal model, benchmark, image, Real DLC Hardware, or Verified vLLM Alignment acceptance claims.
