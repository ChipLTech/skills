# Model Adaptation Stable Decisions

shared_contract: vllm-cl-contract/v1

Model Adaptation owns capability analysis and the smallest traceable compatibility decision for one explicit model. Main-to-Main owns upstream alignment, baseline recovery, global impact analysis, and finalization. Delegation flows from Main-to-Main to Model Adaptation and sealed evidence flows back; the child never invokes or assumes parent ownership.

Model execution and runtime-dependent validation normally occur in the declared Docker Container Execution Contract. Treat every path as an execution-locus coordinate: `/work/vllm`, `/work/vllm-cl`, model paths, package metadata, worker files, and artifacts inside the container are not Host paths unless an explicit mount mapping says so. Host path absence establishes only that the current Host shell cannot access the container coordinate. It does not establish missing source, model assets, or a failed validation. Record container identity, working directory, package/source identity, device mapping, and the locus of every retained artifact before attribution. Record a Host-to-container mount mapping only when relating coordinates across those namespaces; image-internal files and container volumes instead require their container ownership and content identity.

TP is a model-specific deployment decision derived from approved weights, model configuration, dtype, quantization, capacity, and the target profile. Fixed regression TP values are not defaults for arbitrary models.

The shared contract owns API, lifecycle, Chunked Prefill, and DLC Runtime behavior evidence. This package names their evidence states but does not reproduce their executable assertions. Dummy is available only after sealed real-weight failure and explicit approval, remains diagnostic-only, and cannot contribute to acceptance.

Exact Ticket 06 v12 Model Adaptation completed operational regression with `authoritativeness: operational_only`, `acceptance_eligible: false`, alignment unchanged, and finalization `none`. That evidence does not establish Real DLC Hardware acceptance, Verified vLLM Alignment, request-correlated Chunked Prefill, DLC Runtime dispatch, DLCCL/LYP execution, a specific Attention implementation, Triton non-execution, compile/Dynamo non-execution, or rank-to-device allocation. New targets require their own sealed evidence. Model Adaptation does not recover, update, finalize, or claim Verified vLLM Alignment.

For quantized TP paths, separate checkpoint quantization semantics from physical kernel alignment. Record checkpoint group size, effective execution group, `g_idx`, `desc_act`, packed-axis permutation, rank-local logical partition, scale/qzero lookup ownership, qweight identity, physical shape, and padding contribution. Group refinement is eligible only when each refined group exactly partitions the checkpoint group and logical shard, group-index/permutation transformation preserves dequantization lookup semantics, qweight remains unchanged, padding is provably zero-contribution, and the exact DLC Custom Kernel supports the effective group. Otherwise close the route before launch. Resolve the historical rationale through `chipltech-context` at `case-studies/hy3-gptq-tp8-graph-adaptation.md`; do not copy its group64 or TP8 values into another model.

For serving runtime failures, the target boundary is the sealed lifecycle stage and exact symptom, not merely process failure. HTTP 500, worker cancellation, Engine death, and cleanup warnings may be consequences of an earlier asynchronous DLC Custom Kernel failure. Graph/speculative/MTP diagnosis must preserve scheduler state, actual Graph dispatch size, final worker environment, and one-variable deltas. Blocking or debug configuration that creates an initialization or weight-load stall has not reproduced a decode failure and cannot identify its cause. Resolve the detailed procedure through `chipltech-context` at `runtime-debugging/runtime-troubleshooting.md`; this skill owns only the gate.

For Graph failures, first compare Eager and Graph under the same model, weights, TP/EP, request, package, and worker identities. Use sparse synchronization at parent/child lifecycle boundaries to establish the last completed parent and first incomplete child; the final visible kernel or timeout is only an observation point. A direct harness that completes the same primitive falsifies a universal-kernel claim but does not erase a model-route lifecycle incompatibility. Keep any semantic adapter behind an exact route predicate and prove ownership, zero-fill or other invariants, and result equivalence before Real DLC Hardware use. Remove diagnostic synchronization and rerun the uninstrumented stability workload before reporting acceptance.

Performance diagnosis is owned by `diagnosing-bugs`. Model Adaptation may consume a bounded diagnosis only after it demonstrates a model/backend compatibility mismatch for an exact workload and preserves correctness, execution ownership, and uninstrumented scope. Instrumented timing improvement is not a stable performance baseline, Real DLC Hardware acceptance, or Verified vLLM Alignment; a backend flag observed in one source identity is not a universal capability rule.

## Cross-Repository Interface Boundary

The public operator schema is the caller contract. The ordered KernelDesc descriptor is the host launch contract. The exact DLC Custom Kernel entry ABI and binary are the execution contract. An optional public argument being `None` does not prove that its descriptor slot is absent. Record all three in the applicable v1 capability/dependency evidence before declaring an active model path compatible; this decision does not add fields to `vllm-cl-contract/v1`.

When main exposes a broader schema than a frozen DLC Custom Kernel supports, preserve caller compatibility and use a bounded host adapter only for the exact proven Kernel ABI. Reject unproved routing metadata, scoring modes, zero-point modes, qzeros combinations, group sizes, dtypes, layouts, and collective semantics before launch. Do not narrow a generic public schema or add a model-name exception to hide a binary pairing problem.

Repository investigation scope, modification scope, and PR count are independent. A no-change DLC_Custom_Kernel Repository conclusion can be correct when the selected path intentionally consumes a frozen binary capability subset. Classify source absence separately from artifact or ABI pairing, and assign each change to its actual owner: generic framework behavior to upstream vLLM, DLC integration behavior to vLLM-CL, public dispatch and KernelDesc packing to the current PyTorch/extension owner, Kernel implementation to DLC_Custom_Kernel Repository, and native pairing to the owning runtime component.

## Campaign-Derived Diagnostic Gates

For a stable wrong-output symptom, use an ordered seam diagnosis: loaded-weight integrity, deterministic synthetic fused-op checks, rank-local operations, TP collectives one at a time, one-variable diagnostic probes, real-model Model-Site Dump comparison, then a same-family cross-model comparison. Seal the workload and change one variable per epoch. The first material divergence identifies a boundary to minimize; it does not establish that boundary as the sole cause.

Synthetic input can falsify a catastrophic single-op hypothesis but cannot replace real-model intermediates. A smaller same-family model passing in the same environment can falsify a platform-global failure hypothesis, but it supplies only supporting evidence for a model-depth or scale hypothesis. Model Adaptation must preserve that distinction between confirmed issue, falsified hypothesis, and unverified cause.

The Qwen3-32B Block-256 campaign confirmed a reproducible BF16 DLCCL `o_proj` all-reduce divergence while a CPU collective probe failed to repair the end symptom. Treat collective source identity, dtype, shape, rank order, and replay equivalence as required evidence; do not generalize one source identity into a universal DLCCL rule. Resolve the authoritative case study through `chipltech-context` at `case-studies/qwen3-32b-dlc-block256-diagnosis.md` instead of duplicating its environment-specific commands here.

Distributed qualification is route-specific and closed-world. Native DLC_CL symbol availability, PyTorch ProcessGroup support, vLLM communicator routing, model reachability, active MoE dispatch/combine, and custom-kernel descriptor ABI/binary identity are independent facts and cannot substitute for one another. An inactive anti-route remains explicit; every active route must be in the required set and qualified before model launch. Missing hardware is `blocked_missing_hardware`/`not_verified`, never a fixture pass.

For topology/payload-aware collectives, the initialized communicator owns topology discovery, formal algorithm lookup, rank/root metadata, and rank order. The framework supplies actual payload and other selection inputs, caches by every input that can change the decision, and transports only a stable strategy/metadata ABI. The DLC Custom Kernel dispatches that strategy and reserves assertions for illegal strategy or descriptor contradictions; payload capacity, alignment, missing root metadata, and an unsupported preferred implementation are pre-launch capability decisions.

Fallback uses validate-then-commit. Reset the result to Unknown before validating a fallback candidate, then commit it only after its graph, channel, complete unique in-range rank order, metadata, payload, and alignment prerequisites pass. A candidate label is not qualification, and world size is not topology evidence. Resolve the historical rationale and review-derived boundary matrix through `chipltech-context` at `case-studies/qknorm-topology-aware-allreduce-selection.md`; do not copy its model-specific thresholds or strategy IDs into a new adaptation.

When the requested output is an adaptation analysis report rather than new execution, separate the Evidence Ledger from the reader-facing Decision Summary and its Technical Attachment. Preserve the distinction between route feasibility, adaptation completion, and stable delivery. Resolve actual `KernelDesc::launch("custom_xxx")` names through the target call chain and registry; do not infer them from module names or another model's kernel summary. Keep DLCCL communication separate from model-kernel gaps. For performance, bind input/output tokens, TP/EP, concurrency, TPOT, TTFT, single-request versus service throughput, and source identity before converting units. Use the report prompt at `chipltech-context` -> `prompt-examples/vllm-cl-model-adaptation-analysis-summary.md` when only report production is requested; it does not replace this skill's compatibility analysis or qualification gates.

The bounded DLCCL runner owns external watchdog, rank-exit aggregation, task-owned process-tree cleanup, and post-failure health recording. Its producer evidence can support later decisions but never constitutes formal acceptance. `modelzoo-image-validation` independently reruns model, benchmark, and image gates. Claim Boundary: controlled fixtures establish only contract, timeout, rank aggregation, cleanup, and blocker behavior; they do not establish Real DLC Hardware collective correctness or acceptance.

## Hermes Execution Boundary

In the recorded campaign profile, five Hermes oneshot invocations completed without executing required tools. This is operational evidence for that profile, not a universal Hermes capability claim. Execution-mandatory Real DLC Hardware work must use a tool path that produces observable operations and retained evidence.
